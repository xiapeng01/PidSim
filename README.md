# PID 模拟测试台

基于 WPF（.NET 10，MVVM）的 PID 参数整定与对象仿真工具。内置水泵流量计、加热、制冷、Modbus 通信四种仿真对象，可实时观察设定值、过程值、PID 输出与误差曲线。支持参数导入导出，并通过 GitHub Actions 自动打包 NSIS 安装包发布到 Release。

## 功能特性

- 四种可切换的仿真对象：水泵流量计、加热、制冷、Modbus 通信
- 两种 PID 算法：位置式、增量式
- 仿真对象在独立线程按固定 10ms 周期运算，PID 按采样周期 Ts 计算
- 纯滞后环节：按 10ms 索引读取历史输出，支持 0.01s 级别的小数滞后
- Modbus 通信设备：支持 ModbusRtu / ModbusTcp / ModbusRtuOverTcp，输入/输出通道可独立配置或共用通信
- Modbus 支持输入寄存器/保持寄存器、Int16/UInt16/Int32/UInt32/Float、四种字节序，以及“只监控输入”模式
- 实时曲线（左轴设定值/过程值，右轴 PID 输出）、指标卡片、控制器诊断信息
- 参数导入/导出（`.pidsim`）
- 每次构建自动生成版本号；推送后由 GitHub Actions 生成 NSIS 安装包并发布到 Release
- 亮色/暗色主题切换

## 环境要求

- Windows 10 / 11
- .NET 10 SDK（目标框架 `net10.0-windows`）
- Modbus 功能依赖 NuGet 包 `NModbus.Extensions`（项目已引用）
- 打包安装包时由 CI 自动安装 NSIS，本地运行程序不需要 NSIS

## 构建与运行

```bash
dotnet build
dotnet run
```

也可以直接用 Rider / Visual Studio 打开 `PidSimulator.slnx` 运行。

## 使用流程

1. 在“运行设置”选择仿真模型（水泵流量计 / 加热 / 制冷 / Modbus通信）
2. 选择 PID 类型（位置式 / 增量式）
3. 设置设定值 SP、初始 PV、PID 参数与模型参数；Modbus 设备还需配置输入/输出通道
4. 点击“开始模拟”，可随时“停止”；停止状态下可“单步”“复位”“清曲线”
5. 需要保存或复用参数时，使用“导出”生成 `.pidsim` 文件，使用“导入”恢复（运行中不可导入）

约束：

- 运行中不能切换仿真模型，也不能切换 PID 类型，需先停止
- 运行中可以修改参数，修改后立即生效
- “清曲线”会同时清空曲线记录和对象的滞后运算数据；“复位”会重置对象状态、PID 状态与计时

## 仿真模型

### 水泵流量计

| 参数 | 默认值 | 说明 |
|---|---|---|
| 指令下限 / 上限 | -3000 / 3000 | PID 输出映射到流量的量程 |
| 输出下限 / 上限 | -10 / 10 | 流量读数范围 |
| 时间常数 τ | 0.45 s | 一阶惯性时间常数 |
| 滞后时间 Td | 0 s | 纯滞后，0 表示不启用 |

指令先线性映射为目标流量（默认 ±3000 对应 ±10），再经一阶惯性逼近。

### 加热 / 制冷

| 参数 | 默认值 | 说明 |
|---|---|---|
| 环境温度 Ta | 25 ℃ | 指令为 0 时的稳态温度 |
| 满功率温差 ΔT | 60 ℃ | 满功率时相对环境温度的最大温差 |
| 满功率指令 | 3000 | 对应满功率的指令值，建议与 PID 输出上限一致 |
| 时间常数 τ | 30 s | 热惯性时间常数 |
| 滞后时间 Td | 0 s | 纯滞后，0 表示不启用 |

加热只响应正指令，制冷只响应负指令。制冷模型无法主动升温，温度低于设定值时只能被动回到环境温度。

### 滞后时间说明

对象每次运算的输出会插入历史列表下标 0，滞后读数取 `下标 = round(Td / 0.01)`：

| Td | 下标 | 实际滞后 |
|---|---|---|
| 0 | 0 | 无 |
| 0.01 s | 1 | 10 ms |
| 0.5 s | 50 | 500 ms |
| 1 s | 100 | 1000 ms |

历史长度不足时读数为 0；列表容量为 `下标 + 1`（上限 100000），不会无限增长。

### Modbus 通信设备

| 链路类型 | 需要配置的参数 |
|---|---|
| `ModbusRtu` | 串口、波特率、数据位、校验位、停止位 |
| `ModbusTcp` | IP 地址、端口 |
| `ModbusRtuOverTcp` | IP 地址、端口 |

两个通道共有的参数：站号（1~247）、寄存器地址、读写周期、寄存器区、数据类型、字节序。地址输入框可切换十进制/十六进制；串口下拉框展开时自动列出本机串口。

| 寄存器区 | 读取方法 | 写入 |
|---|---|---|
| 输入寄存器（只读） | `Read*R` | 不支持 |
| 保持寄存器（可读写） | `Read*RW` | `Write*RW` |

| 数据类型 | 占用寄存器数 |
|---|---|
| `Int16` / `UInt16` | 1 |
| `Int32` / `UInt32` / `Float` | 2 |

字节序可选 `ABCD`、`BADC`、`CDAB`（默认）、`DCBA`。输入与输出可以使用不同通信类型和参数，也可勾选“与输入共用同一通信”；此时输出沿用输入链路参数与字节序，但仍可独立设置站号、寄存器地址、数据类型和写入周期。

勾选“只监控输入值”后不执行 PID 控制、不写入输出通道，仅按周期采集输入并绘制曲线。输出通道只能写保持寄存器。

## PID 参数

| 参数 | 默认值 | 说明 |
|---|---|---|
| Kp 比例 | 100 | 比例增益 |
| Ki 积分 | 200 | 积分增益，积分项为 `Ki × Ts × Σe` |
| Kd 微分 | 0 | 微分增益 |
| 输出下限 / 上限 | -3000 / 3000 | PID 输出限幅 |
| 采样周期 Ts | 0.1 s | PID 计算周期 |
| 增量限幅 Δmax | 1000 | 增量式单步输出变化限幅 |
| 积分限幅 Σe | 200 | 位置式误差累加和限幅，兼作抗积分饱和 |

## 调参提示

制冷模型稳态所需指令为 `|u| = (Ta − SP) × 3000 / ΔT`，而积分最大只能提供 `Ki × Ts × Σe`，二者需满足：

```
Ki × 0.1 × Σe ≥ (Ta − SP) × 3000 / ΔT
```

否则温度会停在半路到不了设定值。示例工况 Ta=25、ΔT=40、SP=10、τ=30、Td=0 时：

| Kp | Ki | Σe | 超调 | 进入 ±0.5℃ |
|---|---|---|---|---|
| 100 | 80 | 200 | 0.84 ℃ | 37 s |
| 100 | 100 | 200 | 1.42 ℃ | 45 s |
| 100 | 200 | 200 | 2.28 ℃ | 54 s |

## 参数导入导出

工具栏“导出”会生成 `.pidsim` 文件（JSON 格式），包含 PID 参数、仿真模型参数以及 Modbus 输入/输出通道参数，不包含曲线数据和运行状态。“导入”在停止状态下可用，导入后重建控制器与仿真对象并清空曲线。文件格式带 `FormatVersion`，当前版本为 `1`。

## 自动版本与发布

每次构建按 `0.1.天数.秒数/2` 动态生成版本号：

- 第三段：自 2000-01-01 起的天数
- 第四段：当天零点起经过秒数的一半（程序集版本号每段上限 65534）
- `FileVersion` / `InformationalVersion` 使用该动态版本；`AssemblyVersion` 固定为 `0.1.0.0`，避免 WPF 标记编译时版本漂移

推送到任意分支后，GitHub Actions（`.github/workflows/release.yml`）会：

1. 一次性计算版本号并通过 `-p:Version` 传给构建
2. 发布 `win-x64` 自包含单文件程序
3. 使用 `installer/PidSimulator.nsi` 生成安装包
4. 创建 Release，标签为 `v<版本号>`，附件为 `PidSimulator-<版本号>-win-x64-setup.exe`
